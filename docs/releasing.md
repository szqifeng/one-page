# 发布流程

本仓库当前没有自动发布任务。CI 只检查代码并构建镜像，不推送镜像或部署服务。

1. 确认 main 的 CI 成功，检查业务流程、权限和数据库升级兼容性。
2. 更新 package.json 版本，并将 CHANGELOG.md 中本次变更归入带日期的版本标题。版本号采用 major.minor.patch；不兼容变更需明确迁移方案。
3. 更新需求与部署文档，提交并推送发布准备改动。
4. 在验证通过的提交上创建带注释的版本标签，如 v0.1.0，再推送该标签。
5. 在 GitHub 创建对应 Release，附变更记录、部署方法、兼容性说明和已知限制。分发源码或镜像时保留 LICENSE 与版权声明。

生产升级前独立备份 PostgreSQL，记录旧提交或镜像版本，再按部署说明重建服务并检查健康接口与关键操作。需要回退时先判断数据库兼容性；涉及不兼容的数据变更，应按已验证的数据库恢复方案执行。

GitHub 分支保护与私密漏洞报告需要维护者在仓库设置中启用，不会因为添加这些文件而自动生效。建议要求 CI 的 verify 检查通过后再合并。
